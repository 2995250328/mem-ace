 一、先稳住 ACE-G Global Baseline

  当前 ACE-G global 已经能跑出较好效果，但里面有不少隐式行为，会让实验解释变困难。第一
  批修改不是追求性能，而是让结果可信。

  1. deterministic FPS

  现在 global compressor 选 latent 坐标时用 FPS，但初始点来自 torch.randint()。这意味
  着：

  同一个 memory + 同一个 checkpoint
  可能在 S1 / S2 / test 时选到不同 latent token 坐标

  这会影响：

  compressor query
  global attention distance bias
  fusion memory_p PE
  head 最终看到的 fused feature 分布

  所以第一步应该让 FPS 可复现。推荐最小改法是 deterministic start，例如选距离
  scene_center 最远的点，或者基于稳定 index/score 选起点。这样每次压缩同一个 memory 都
  得到同一组 latent 坐标。

  2. 显式化 key layer

  当前 memory 是五层特征：

  slice 0: intermediate[0]，可能是 MapAnything info-sharing 前的 input
  slice 1: intermediate[6]
  slice 2: intermediate[12]
  slice 3: intermediate[18]
  slice 4: final

  compressor 当前写法是：

  raw_key_feats = _get_layer_slice(pooled_features, 1)

  但 helper 内部有 layer_idx + 1，所以实际取的是：

  slice 2 = layer 12

  这不是普通的 layer_idx=1 -> slice 1。这可能是有意跳过 slice 0，但现在不清楚。需要改成
  显式配置：

  lmc_key_slice_idx = 2
  key_layer_label = 12

  并在日志和 checkpoint config 里保存。否则之后做 layer ablation 时会混乱。

  3. 保存完整 LMC config

  现在一些结构性参数没有完整存入 checkpoint，比如：

  pe_normalize_input
  geo_sigma
  num_fine
  num_coarse
  backbone_feature_dim
  key_slice_idx
  layers_idx
  scene_scale policy
  fusion geometry mode

  如果训练和测试重建模型时默认值不一致，评估可能不是同一个模型结构。这个要补齐。

  4. 统一 reprojection / invalid loss

  S1 和 S2 都是 ACE-style reprojection supervision，但代码里有多份重复实现。重复路径里
  有细微差异，比如 invalid loss clamp、dyntanh step、mask 处理等。

  这会导致一个问题：

  你以为 S1/S2 监督一致
  实际它们可能在一些边界行为上不一致

  建议抽一个统一 helper，让 S1 sampled、S1 full-map、S2-G 都走同一套 reprojection /
  invalid loss 计算。

  5. S1 sampled loss time-axis 显式化

  现在 sampled S1 在某些路径里 iter_for_loss=0，意味着 dyntanh 一直停在最宽松状态。这个
  行为要么是有意的 curriculum，要么是历史遗留。无论如何都应该显式化：

  s1_loss_step_mode = fixed_zero / per_iter / global_monotonic

  至少日志要说清楚 S1 loss 用的 step 是什么。

  6. S2 compressor 冻结从隐式改为显式

  当前 S2 不训练 compressor，主要靠：

  _compress_memory() with no_grad
  optimizer 不包含 compressor

  这在当前代码里够用，但未来一旦有人在 S2 里 live forward compressor，就可能泄漏梯度。
  建议加明确 helper：

  _set_compressor_trainable(False)

  S1 前打开，S2 前关闭。

  二、Global Compressor 的修改思路

  Compressor 现在不是完全粗糙，它已经有：

  FPS latent coords
  query = PE(latent_coords - scene_center)
  key = single layer feature
  value = all-layer concatenated feature
  global attention + learned distance bias
  scale token global shift

  但几个点需要优化。

  1. key layer ablation

  当前默认实际是 layer 12。我不建议直接改成 final，也不建议直接用 slice 0。

  判断如下：

  - slice 0 可能是 MapAnything attention 前 input，太原始，不适合作 key。
  - final 语义强，但可能过度聚合，局部区分性下降。
  - layer 12 / layer 18 更可能适合作 key。
  - value 继续用全层 concat，因为它负责保留完整 memory 内容。

  推荐实验顺序：

  A0: current layer 12
  A1: layer 18
  A2: layer 6
  A3: final
  A4: learned scalar mix

  learned scalar mix 是：

  key_feat = sum_l softmax(w_l) * feat_l
  value = concat(all_layers)

  这样 key 仍然是一层维度，不像全层 concat key 那样增大参数和复杂度。

  2. 位置编码 PE 的尺度问题

  现在 PE 是随机 Fourier：

  coords -> random Gaussian projection -> sin/cos -> MLP

  问题是它没有稳定物理尺度。coords = point - scene_center，但不同 scene 大小不一样，坐
  标数值范围不同，PE 频率意义就变了。

  建议先定义：

  coords_norm = (coords - scene_center) / scene_scale

  scene_scale 可以来自：

  bbox radius
  point std
  percentile radius

  它要统一用于：

  compressor PE
  fusion PE
  global distance bias

  先别急着搞 full normalized-coordinate training，只是先让几何编码尺度稳定。

  3. Fourier PE 可以做低风险 ablation

  当前随机 Fourier 有点黑箱。可以后续测试：

  random Fourier baseline
  fixed multi-scale Fourier
  fixed Fourier + raw xyz
  fixed Fourier + raw xyz + radius
  shared frequency basis between compressor/fusion

  但这些要放在 scene_scale contract 之后，否则实验解释不清。

  4. global distance bias 太单一

  现在是：

  geo_bias = MLP(log(dist_sq))
  attn_logits = qk + geo_bias

  它只看一个标量距离，且是 raw scene scale。优化方向：

  dist_norm = sqrt(dist_sq) / scene_scale
  geo_feat = [
    log1p(dist_norm),
    dist_norm,
    exp(-dist_norm^2 / sigma1^2),
    exp(-dist_norm^2 / sigma2^2),
    exp(-dist_norm^2 / sigma3^2),
  ]
  geo_bias = MLP(geo_feat)
  attn = content_logits + alpha_head * geo_bias

  关键是加 alpha_head gate，并初始化小一点，让模型从接近 content-only attention 开始学
  geometry 的权重。

  方向特征也可以考虑：

  direction = (memory_point - latent_coord) / distance

  但这个复杂度高，应该排在 normalized distance basis 之后。

  三、Fusion 是近期最值得改的模块

  当前 fusion 是：

  q = q_proj(query_feats)
  k = k_proj(memory_z)
  pe = PE(memory_p - scene_center)
  v = v_proj(memory_z + pe_proj(pe))
  attn = softmax(q @ k)

  也就是说：

  geometry 只影响读出来的 value
  不影响 query 选择哪个 memory token

  这就是 GeoMatch 文档里最有价值的观察。

  1. GeoMatch Fusion v1

  建议近期实现为 controlled ablation，不替换整体架构。

  目标结构：

  pe = PE(memory_p - scene_center)
  pe_mem = pe_proj(pe)

  gate_k = sigmoid(key_geo_gate)
  gate_v = sigmoid(value_geo_gate)

  q = q_proj(query_feats)
  k = k_proj(memory_z + gate_k * pe_mem)
  v = v_proj(memory_z + gate_v * pe_mem)

  attn = softmax(q @ k)
  out = attn @ v

  初始化：

  key_geo_gate   = -4.0
  value_geo_gate =  0.0

  含义：

  key_geo_gate=-4.0 -> sigmoid 很小
  所以一开始 key 仍接近当前 feature-only key
  避免 geometry 一上来破坏 matching

  value_geo_gate=0.0 -> sigmoid 约 0.5
  保留一定 value geometry

  这个改法比“直接把 PE 加进 key”更稳，因为 geometry 强度是可学习的。

  2. 保留当前 value-only fusion 作为 baseline

  不要直接覆盖当前 fusion。应该有开关：

  fusion_geo_mode = value_only / gated_key_value

  默认最好先保持当前行为，新增实验再开启 gated_key_value。这样老 checkpoint 和老实验语
  义不会被破坏。

  3. fusion attention diagnostics

  在加任何 usage loss 之前，必须先知道 attention 到底怎么用 token。

  需要记录：

  attention_entropy
  token_usage
  effective_token_count
  avg_max_attention
  gate_k
  gate_v
  raw_feature_norm
  fused_feature_norm

  定义大致是：

  attn: [B, heads, Nq, K]

  token_usage = mean(attn over B, heads, Nq)
  effective_token_count = exp(entropy(token_usage))
  avg_max_attention = mean(max(attn over K))

  这些指标回答几个问题：

  是不是少数 token 吃掉所有 query？
  attention 是太软还是太硬？
  geometry gate 有没有真的学起来？
  fusion 是小修正还是彻底重写 raw feature？

  4. usage loss 不是第一步

  如果发现 token collapse，再加：

  L_usage = KL(token_usage || Uniform)
  lambda_usage = 0.001 / 0.003 / 0.01

  但这个 loss 有风险：强行均匀使用 token 不一定符合真实场景，有些 token 本来就应该更常
  用。所以它必须是诊断后的 ablation，不是默认设计。

  而且先只放 S1：

  S1 trains compressor + fusion + head
  S2 compressor frozen and cached

  S2 不应该加 compressor-dependent 新目标。

  5. fusion residual gate

  当前：

  x = LayerNorm(query_feats + attention_out)

  这可能让 fusion 变成大幅 feature reparameterization。可以后续加：

  x = LayerNorm(query_feats + residual_gate * attention_out)

  但这个优先级低于 geometry key/value 和 attention diagnostics。

  四、哪些 GeoMatch 文档里的内容先不做

  这些不是没价值，而是不适合现在混进第一轮。

  1. Anchor-assisted residual branch

  思路是：

  query feature -> route to memory anchors
  predict delta relative to anchor
  P = anchor + delta

  它有价值，因为 scene coordinate 本质上更适合局部残差回归。但近期不应替换 ACE head。

  后续安全版本应是 auxiliary branch：

  主输出仍是 ACEHead
  anchor branch 只加小权重辅助 loss
  lambda_anchor = 0.05 / 0.1

  并做：

  ACE-only
  ACE + auxiliary
  anchor-only
  Top1
  Top3

  在这之前，不要让它成为主输出。

  2. Full normalized-coordinate training

  多场景训练确实需要：

  P_norm = (P_world - mu_scene) / sigma_scene

  但当前先不要改 target。原因是它会影响：

  scene coord recovery
  camera-space transform
  invalid depth target
  reprojection loss
  checkpoint eval
  DSAC/PnP

  近期只吸收其中的轻量部分：

  用 scene_scale 规范化 PE 和 distance bias

  完整 normalized target 要另开分支，先证明单场景等价，再做多场景。

  3. DSD-style local/deformable compressor

  这个方向是让 latent token 不只是 FPS coverage，而是学会向任务有用区域偏移：

  FPS coords -> local KNN -> local attention -> bounded offset

  但它会改变 compressor output distribution。ACE-G 的 S2 又是 cached compressor
  output，所以分布漂移风险很高。必须等 deterministic FPS、key ablation、fusion
  diagnostics 都稳定后再做。

  4. Sub-memory routing

  这个适合大场景：

  query descriptor -> select top-1/top-2 sub-memory -> ACE-G inference

  但它解决的是大场景 scaling，不是当前 global compressor/fusion 的核心问题。应该等单
  memory global 先稳定。

  ———

  五、现在推荐的执行顺序

  最合理的顺序是：

  0. 固定 baseline
     - 固定命令、seed、memory、评估路径

  1. Engineering hygiene
     - deterministic FPS
     - key layer 显式化
     - config 完整保存
     - S2 compressor 明确冻结
     - loss path 统一

  2. Compressor interpretability
     - key layer ablation
     - scene_scale contract
     - PE / distance bias diagnostics

  3. GeoMatch Fusion v1
     - gated key/value geometry
     - 保留 value-only baseline
     - key_geo_gate=-4.0
     - value_geo_gate=0.0

  4. Attention diagnostics
     - entropy
     - token usage
     - effective token count
     - avg max attention
     - gate curves
     - raw/fused norm

  5. Conditional usage loss
     - 只有 token collapse 明确存在时才做
     - 只先放 S1
     - lambda = 0.001 / 0.003 / 0.01

  6. Later research
     - anchor auxiliary branch
     - full normalized target
     - DSD/local compressor
     - sub-memory routing

  一句话总结：先把 ACE-G global 的随机性和隐式语义消掉，再做最局部、最可控的 GeoMatch
  Fusion 改造；先看 attention 怎么用 token，再决定要不要加 usage loss；更大的 MoE、
  anchor、normalization、DSD 都先作为中长期研究路线。
