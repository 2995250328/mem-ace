## 1. Problem Restatement

当前任务不是单独优化一个选帧函数，而是为 `mem-ace` 设计一套**完整的、可落地的 memory construction system**。这套系统必须同时解决四个耦合问题：

1. **小/中场景如何构建 single-forward memory**
   保持 MapAnything 在一次 multi-view forward 内得到统一的 reference-conditioned memory，而不是把小场景过早切成多个独立 chunk。你当前代码的主路径本身就是“先选 `memory_views`，再整体送入一次 `infer()`”的 single-forward 结构 。

2. **single 分支里具体如何选帧**
   不是固定取 K 张，而是要在 coverage、support、topology、reference-risk 之间做统一优化。

3. **什么时候自动停止继续加帧**
   只给 `max_views` 上限，让系统自己判断“这个 single reference-local domain 已经够好了”。

4. **什么时候切到大场景分支**
   不是按场景名字或固定阈值拍脑袋切，而是判断：当前 scene 是否还存在一个可行的 single reference-local domain；若不存在，则进入 cluster-local memories。

结合这几轮 review，系统还必须满足一个更强的约束：

* **reference contract 必须先于选帧确定**。
  之前的 review 已经指出：如果 memory feature 是 reference-conditioned，而你又直接把它绑定到 world-frame geometry，上层 policy 再聪明也可能建立在错误的坐标语义上 。
* 但最新 review 也指出：`feature frame ≈ reference camera frame` 这个假设本身未被证明，因此不能直接把它写死成唯一正确语义，而应设计成**可验证、可降级的 contract** 。

因此，最终设计目标应当表述为：

> **设计一套 Reference-Consistent Adaptive Memory Construction 系统：在 MapAnything-conditioned relocalization 中，先定义并验证 memory 的 reference-local contract；再判断 single reference-local domain 是否存在；若存在，则用 topology-aware + reference-risk-aware + auto-stop 的 single-forward construction 构建 memory；若不存在，则退化到 ACE-style cluster-local memories，并通过 independent ensemble 在 world frame 上完成最终 relocalization。**

系统约束也需要明确收敛，避免继续膨胀：

* 当前阶段**不研究** BSE / voxel pooling / point density optimization；
* **不更换 backbone**；
* **不引入 learned query routing**；
* **不引入 learned scene policy**；
* **不做 cross-cluster feature fusion**；
* cluster 分支只作为 fallback，而不是默认路径 。

---

## 2. Design Space Exploration

### Paradigm A：固定 K 的 single-forward 选帧系统

**核心思想**
对所有 scene 固定选择 K 张 memory views，然后一次性构建 single-forward memory。

**优点**
实现简单，易于复现，工程改动最小，也与当前 `run_memory_extraction.py` 的结构最接近 。

**缺点**
它假设所有场景对 memory budget 的需求一致。小场景会过选，大场景会欠选。更严重的是，它没有回答“当前这批 views 是否仍然属于一个 single-reference-safe domain”。

**适用场景**
仅适合作为 baseline，不适合作为最终系统方案。

**放弃原因**
它无法吸收 review 提出的两个关键问题：reference contract 与 scene-adaptive branching。

---

### Paradigm B：始终 single-forward，但引入自适应停帧

**核心思想**
所有 scene 都走 single-forward；只给 `max_views`，通过 adequacy 判据自动 early stop。

**优点**
非常符合小场景约束，能够保留统一 reference-conditioned memory，不必过早切 chunk。

**缺点**
它只解决“选多少张”问题，不解决“一个 single reference-local domain 是否根本存在”。如果 scene 本质上是多区域弱连通或 reference-risk 很高，再好的 auto-stop 也无效。

**适用场景**
compact indoor scene、局部区域明确、相机轨迹相对集中。

**放弃原因**
作为系统唯一范式不够；它缺少大场景 fallback。

---

### Paradigm C：所有场景统一 cluster/chunk 化

**核心思想**
无论场景大小，一律先 cluster，然后每个 cluster 单独构建 memory。

**优点**
对大场景最自然，可扩展性最好。

**缺点**
小场景会被过度拆分。你前面已经明确指出：MapAnything 的 memory feature 是 reference-conditioned 的，小场景切成多个 chunk 可能引入多个 reference-local subspaces，带来额外 gap 。

**适用场景**
campus 级别、多建筑、多分区弱连通的大场景。

**放弃原因**
不适合作为默认系统，只能做 fallback。

---

### Paradigm D：Reference-Consistent Adaptive Hybrid（纯几何/规则式 gate）

**核心思想**
先定义 reference-local contract；然后用 coverage、topology、support、reference-risk 等轻量几何统计判断 single domain 是否存在；若存在走 single-forward，否则 cluster。

**优点**
结构清楚，可解释性强，工程成本可控。

**缺点**
最新 review 已指出，仅凭几何/拓扑统计并不能保证 MapAnything 的 reference-conditioned memory 真处于稳定工作域，因为 `feature frame ≈ reference camera frame` 可能不严格成立 。

**适用场景**
第一版可作为低成本 policy。

**局限**
它可能错过“几何上看起来可行、但 MapAnything probe 实际不稳”的场景。

---

### Paradigm E：Reference-Consistent Adaptive Hybrid（两级 gate：light gate + probe gate）

**核心思想**
系统先用轻量几何统计筛掉明显不合格的 candidate/reference；再对少量 top-M reference candidates 做 bounded MapAnything probe，判断 single reference-local domain 是否真的存在。若存在，则构建 single-forward memory；否则进入 cluster-local memories。

**优点**
它兼顾了：

* 小场景的统一 single-forward memory；
* 大场景的 fallback；
* 对 review 中“Assumption A 证据不足”的回应，因为最终 single-domain decision 不是纯几何拍脑袋，而是 probe-assisted  。

**缺点**
比纯规则系统更重，policy 变成 probe-based policy，不再是完全轻量的 selector。最新 review 也指出这一点需要在研究表述中说清楚 。

**适用场景**
这是当前最合适的最终系统范式。

---

### Paradigm F：end-to-end learned policy / learned query routing

**核心思想**
训练一个 policy 网络决定 reference、selected views、cluster routing，甚至训练一个 learned router 为 query 选择 cluster。

**优点**
潜力大。

**缺点**
变量过多，会把当前研究问题从 memory construction 膨胀到 policy learning / routing learning / meta-optimization。与你当前“先建立可解释、可验证系统”的阶段不匹配。

**放弃原因**
当前阶段明确不做 learned scene policy，也不做 learned query routing 。

---

### 结论

最终选择 **Paradigm E：Reference-Consistent Adaptive Hybrid with Two-Level Gate**。

理由是：

* 它保留了 small-scene single-forward 的正确默认路径；
* 它把 cluster 作为 fallback，而不是默认；
* 它吸收了 review 中对 reference contract、probe consistency、query interface、cluster failure stop 的全部关键批评；
* 它仍然是一个**模块化、可调试、可分阶段实现**的系统，而不是一次性引入过多学习模块。

---

## 3. Selected System Architecture

最终架构选择为：

## **Reference-Consistent Adaptive Memory Construction v3**

这是一个**模块化、分层、自适应**的系统，由七个核心模块组成。

### Module 1：Contract Manager

职责：

* 定义 memory 的 reference-local contract；
* 管理两级假设：

  * **A1**：features are reference-conditioned；
  * **A2**：features are approximately reference-camera-frame equivariant。
    最新 review 明确建议把 A1/A2 分开，避免直接写死强假设 。
* 根据 Q1 sanity check 结果选择 contract mode：

  * **C0: reference-conditioned-only**
  * **C1: reference-coordinate learning**

### Module 2：Scene Graph Builder

职责：

* 从 poses / camera centers / covisibility 构建全局 scene graph；
* 计算 scene extent、reference-distance、supportability、graph connectivity 等统计；
* 为后续 reference candidate generation 和 light gate 提供输入。

### Module 3：Reference Candidate Generator

职责：

* 生成 top-M reference candidates；
* 来源包括 mean-center proximity、graph centrality、average covisibility、low-risk probe heuristic；
* 避免穷举所有 reference。

### Module 4：Feasibility Controller

职责：

* 执行两级 gate：

  * **Light gate**：coverage/topology/reference-risk 粗筛；
  * **Probe gate**：bounded MapAnything probe。
* 判定 single reference-local domain 是否存在。

### Module 5：Single-Domain Constructor

职责：

* 在 single-forward 模式下，执行：

  * reference-risk-aware TA-ASB
  * adaptive stop
  * topology-constrained repair
* 最终生成 single memory。

### Module 6：Cluster Planner & Cluster-Local Constructor

职责：

* 若 single domain 不可行，则执行 ACE-style hierarchical clustering；
* 采用 split-until-safe，但带硬停止条件；
* 每个 cluster 内仍然复用 Single-Domain Constructor。

ACE 原版 README 已明确 cluster/ensemble 路线是正式设计的一部分 ，而 `dataset_origin.py::_cluster()` 已给出层次式二分 kMeans 的具体实现 。

### Module 7：Relocalization Interface

职责：

* 对 single memory 或 multiple cluster-local memories 提供统一的 query-time 接口；
* 第一版明确采用：

  * no learned routing
  * no cross-cluster fusion
  * independent ensemble fallback
    这正是最新 review 建议固定的接口形式 。

---

### 选择该架构的原因

它的关键优势在于**把不确定性显式制度化**，而不是假装已经全部解决：

* 不确定 reference feature 是否真是 ref-camera equivariant？
  用 A1/A2 + contract mode 解决。
* 不确定某个 scene 是否还适合 single-forward？
  用 two-level gate 解决。
* 不确定 cluster branch 如何落地？
  用 cluster-local memories + independent ensemble 解决。
* 不确定 query 是否也要跟 cluster reference 走多次 forward？
  第一版明确规定 query backbone feature 只算一次，cluster reference 只作用于 memory side 和输出恢复，这也是 review 要求说清楚的点  。

---

## 4. Detailed Pipeline Design

### Stage 0

### Contract Validation and Contract Mode Selection

**输入**

* 一组 representative scenes
* 同一 selected view set 在不同 `reference_index` 下的 memory construction 结果
* 同一 query 在不同 reference 下的预测结果

**输出**

* `contract_mode = C0 | C1`
* Assumption A2 是否成立的结论

**算法**
先固定 A1：features are reference-conditioned。这个基本成立。
A2 则必须通过 **reference-swap / prediction-equivariance sanity check** 验证，这一点是最新 review 强调的核心 。

Q1 不再检查“points_ref 的刚体可解释性”，因为那对 GT geometry 来说是平凡成立的。真正需要检查的是：

1. 同一 selected set，选 `ref_a` 与 `ref_b`
2. 分别构建 `memory_a` 与 `memory_b`
3. 对同一 query 预测：

   * (P_{ref_a})
   * (P_{ref_b})
4. 恢复到 world：

   * (P_{world}^{a})
   * (P_{world}^{b})
5. 比较：

   * `mean ||P_world^a - P_world^b||`
   * PnP pose difference
   * DSAC inlier overlap
   * matched world points 上的 feature similarity

**表示**

* 若 A2 成立：启用 **C1**

  * learning frame = `ref` / `ref_norm`
* 若 A2 不成立：降级到 **C0**

  * features 只被视为 `reference-conditioned`
  * coordinates supervision 仍以 `world` 为主
  * `points_ref` 只作为几何辅助 / debug 表示

这是整个系统最重要的前置验证，因为 review 已明确指出：如果 A2 不成立，强行 `points_world -> points_ref -> features_ref` 会在形式上自洽、语义上未必自洽 。

---

### Stage 1

### Scene Graph Precomputation

**输入**

* 全部 training views 的 camera poses / camera centers
* covisibility 或你当前代码里的 `covis_strength`
* 可选的 visibility / overlap 统计

**输出**

* `scene_stats`
* `global_view_graph`
* `reference_risk_table`

**算法**

1. 构建 camera centers。
2. 构建 global graph (G=(V,E))：

   * 节点：views
   * 边权：`covis_strength`
3. 计算基础统计：

   * scene extent / bbox diagonal
   * strong-covis graph 的 components
   * giant component ratio
   * supportable ratio
   * pairwise baseline distribution
4. 对每个 potential reference，预计算：

   * `dist_to_ref` 分位数
   * `far_view_budget` 消耗倾向
   * average covis to others
   * graph centrality

**表示**

```python
scene_stats = {
    "extent_diag": ...,
    "supportable_ratio": ...,
    "num_components": ...,
    "giant_component_ratio": ...,
}
reference_stats[r] = {
    "ref_dist_q50": ...,
    "ref_dist_q90": ...,
    "avg_covis": ...,
    "centrality": ...,
}
```

这一步为 light gate 和 reference candidate generation 提供完全共享的底层数据。

---

### Stage 2

### Top-M Reference Candidate Generation

**输入**

* `scene_stats`
* `reference_stats`
* global graph

**输出**

* `reference_candidates = [r_1, ..., r_M]`

**算法**
不穷举全部 reference，而是从以下规则中取并集、去重、排序：

1. mean camera center 最近的若干 view
2. average covisibility 最高的若干 view
3. graph centrality 最高的若干 view
4. reference-risk 最低的若干 view

通常 (M = 4 \sim 8)。

**表示**

```python
reference_candidates = [
    {"ref_idx": r, "seed_score": ...},
    ...
]
```

这一步吸收了前一轮 review 的建议：single-domain 的“存在性”不能靠理想化表述，必须转成 **top-M reference candidates + bounded probe** 的有限搜索 。

---

### Stage 3

### Light Gate: Cheap Feasibility Screening

**输入**

* `reference_candidates`
* `scene_stats`
* `reference_stats`

**输出**

* `light_gate_passed_candidates`

**算法**
对每个 `r_i` 做一次 cheap screening。
不调用重模型，只使用几何/图统计判断它是否值得进入 probe gate。

判断项包括：

* `coverage_potential_ok`
* `topology_potential_ok`
* `ref_risk_potential_ok`

例如：

* `ref_dist_q90 <= tau_ref_q90_light`
* `supportable_ratio >= tau_support`
* `graph components` 不过度碎裂
* bounded FPS/coverage probe 估计不至于明显失败

**表示**

```python
light_gate_result[r_i] = {
    "pass": True/False,
    "reason_codes": [...],
}
```

这里要明确：这是 **light gate**，不是最终 single-domain 决策。
这样可以控制成本，也回应最新 review 对“gate 过度依赖重模型推理”的担忧 。

---

### Stage 4

### Probe Gate: Bounded Single-Domain Feasibility Probe

**输入**

* `light_gate_passed_candidates`
* current MapAnything memory construction stack
* `max_views_probe`

**输出**

* 对每个 candidate reference 的 `feasibility_report`
* 是否存在 single-domain

**算法**
对每个 `r_i`：

1. 以 `r_i` 为 root/reference
2. 运行一次 **bounded selector probe**
   使用 TA-ASB 的简化版，只允许最多选到 `max_views_probe`
3. 对 probe set (S_i) 计算四个判据：

#### A. coverage_ok

* `coverage_mean <= tau_cov_mean`
* `coverage_max <= tau_cov_max`

#### B. topology_ok

* `num_components == 1`
* `isolated_count == 0`
* `degree_min >= tau_deg`

#### C. ref_risk_ok

* `ref_dist_q90 <= tau_ref_q90`
* `ref_dist_max <= tau_ref_max`
* far-view budget 未超限

#### D. probe_ok

这一项必须用 review 推荐的可实现定义，不再抽象成泛分数 

第一版只使用两个指标：

* MapAnything predicted camera pose residual 的 `trans_q90`
* `trans_max`

于是：

```python
probe_ok = (
    trans_q90 < tau_probe_q90 and
    trans_max < tau_probe_max
)
```

**single-domain existence rule**

```python
if any(candidate satisfies A and B and C and D):
    single_domain_exists = True
else:
    single_domain_exists = False
```

然后在所有可行候选中，选择 `single_domain_score` 最优者。

**表示**

```python
feasibility_report[r_i] = {
    "coverage_ok": ...,
    "topology_ok": ...,
    "ref_risk_ok": ...,
    "probe_ok": ...,
    "score": ...,
}
```

这一阶段的本质是：
**policy controller 不是纯几何 policy，而是 probe-assisted policy。**
这点在文档和实验里都必须明确说明。

---

### Stage 5

### Policy Decision

**输入**

* `feasibility_report`

**输出**

* `policy = single_forward | cluster_branch`
* `selected_reference`（若 single_forward）
* `reason_codes`

**算法**
若任一 reference candidate 可行，则进入 single-forward 分支，并取 score 最优者。
否则进入 cluster branch。

**表示**

```python
policy = {
    "decision": "single_forward" or "cluster_branch",
    "selected_reference": ...,
    "reason_codes": [...],
}
```

这里 large-scene gate 的含义已经非常明确：

> 不是“scene 太大就 cluster”，
> 而是“在 top-M reference candidates 中，不存在一个可行的 single reference-local domain，才 cluster”。

这正是最终方案最重要的系统定义。

---

### Stage 6

### Single-Forward Domain Construction

**输入**

* `selected_reference`
* candidate pool
* `contract_mode`
* `max_views`, `min_views`

**输出**

* final single memory

**算法**

#### 6.1 Candidate Pool Construction

沿用当前 `anchor_support_select_views()` 的骨架：

* root/reference
* adaptive scene params
* supportable candidate filtering
* oversampled candidate pool 

但逻辑语义要变成：

> 这是该 reference 下的 **reference-safe candidate domain**。

#### 6.2 Incremental Selection

采用 **Reference-Risk-Aware TA-ASB**

每步选点分数：

[
Score(v \mid S)=
w_c \Delta Cov(v)
+
w_s \Delta Supp(v,S)
+
w_t \Delta Topo(v,S)
--------------------

w_r Risk_{ref}(v,S)
]

其中：

* `ΔCov`：coverage gain
* `ΔSupp`：shared-neighbor support、local support density
* `ΔTopo`：component merge、degree 提升、bridge risk 降低
* `Risk_ref`：ref distance、far-view budget、baseline-to-ref 恶化

第一版不建议在在线 greedy 中直接放重 probe，只在 Stage 4 的 bounded probe 使用它，避免单步选点成本过高。

#### 6.3 Adaptive Stop

只给 `max_views`，不再手工固定最终 K。

stop 条件必须同时满足：

* `coverage_ok`
* `topology_ok`
* `ref_risk_ok`
* `len(S) >= min_views`
* 最近若干步 marginal gain 已饱和

也就是说，只有当当前 selected set 已经构成一个**single-reference-safe domain**，才允许 early stop。

#### 6.4 Topology-Constrained Repair

完成主选择后，允许：

* connectivity repair
* coverage-hole repair

但所有 repair candidate 必须通过 topology gate 和 ref-risk gate，不能为了 coverage 尾部去破坏整个 domain 的稳定性。

**表示**
single memory 在 `C0` 与 `C1` 两种 contract mode 下分别为：

### C0: reference-conditioned-only

```python
memory = {
    "mode": "single_forward",
    "features_conditioned": ...,
    "conditioning_reference": ...,
    "points_world": ...,
    "points_ref": ...,   # optional / debug / auxiliary
    ...
}
```

### C1: reference-coordinate learning

```python
memory = {
    "mode": "single_forward",
    "features_conditioned": ...,
    "points_ref": ...,
    "points_ref_norm": ...,
    "points_world": ...,
    "reference": {...},
    ...
}
```

这里我故意不把字段硬写成 `features_ref`，因为最新 review 认为这个命名过早承诺了“feature 属于 reference coordinate frame”的强语义，这个担忧是合理的 。
因此更稳妥的命名应是 `features_conditioned` 或 `features_memory`，而不是默认 `features_ref`。

---

### Stage 7

### Cluster Planning

**输入**

* 全部 views
* global graph
* policy = cluster_branch

**输出**

* `clusters`
* `cluster_failure_flags`

**算法**
使用 ACE-style hierarchical clustering 作为基础框架：

* 初始所有 views 在一个 cluster
* 每次挑当前最大 cluster
* camera centers 上做 `k=2` split
* 更新 cluster list 

但终止规则不是固定 cluster 数，而是：

> 只要某个 cluster 仍不满足 single-domain feasibility，就继续 split。

同时必须加**硬停止条件**，这是最新 review 明确要求补上的系统定义 ：

* `max_num_clusters`
* `max_split_depth`
* `min_cluster_size`
* `min_views_per_cluster`
* `unsplittable_failure_reason`

若某 cluster 已无法再合理 split，但仍不满足 probe/coverage 等要求，则：

* 标记为 `low_confidence`
* 构建 best-effort memory
* 暴露 failure reason

**表示**

```python
cluster_plan = {
    "clusters": [...],
    "max_depth_reached": ...,
    "unsplittable_clusters": [...],
}
```

---

### Stage 8

### Cluster-Local Memory Construction

**输入**

* `clusters`
* `contract_mode`

**输出**

* cluster-local memories

**算法**
每个 cluster 内部完整复用 Stage 6 的 single-forward domain construction。
换句话说：

* cluster 不是另一套 memory builder
* cluster 只是“先分 domain，再在每个 domain 内做 single-forward construction”

这样系统模块复用最好，逻辑也最统一。

---

### Stage 9

### Query-Time Relocalization Interface

**输入**

* query image
* single memory 或 clustered memories
* `contract_mode`

**输出**

* final pose in world frame

**算法**

#### Single-forward mode

* query backbone feature 计算一次
* 与 single memory 交互
* 若 `C1`：预测 (P_{ref})，再经 `T_ref->world` 恢复到 (P_{world})
* 若 `C0`：直接预测 (P_{world}) 或 world-supervised coordinates
* 运行 PnP / DSAC，输出 pose

#### Clustered mode

第一版固定采用最新 review 推荐的 independent ensemble interface  ：

* no learned routing
* no cross-cluster feature fusion
* query backbone feature 只算一次，不随 cluster reference 改变
* 每个 cluster memory 独立预测
* 若 `C1`：输出 (P_{ref_i})，再恢复到 (P_{world})
* 若 `C0`：直接 world-frame supervision 输出
* 每个 cluster 各自跑 PnP / DSAC
* 按 DSAC score / inlier count 选择最优 pose

这里必须说明一个张力：
如果 memory side 是 strongly reference-conditioned，而 query feature 完全 cluster-invariant，那么 fusion/head 需要学会：

> query feature + reference-conditioned memory → reference-local or world-frame coordinates

这不是自动成立的，因此训练时必须明确把 reference conditioning 信息通过 memory tokens 或 metadata 暴露给 head。这一点是最新 review 提醒的隐藏矛盾，必须在实现中显式处理 。

---

## 5. Failure Modes and Engineering Risks

### 风险 1：Assumption A2 不成立

**问题**
若 MapAnything feature 只是 reference-conditioned，而不是 reference-camera-frame equivariant，那么强行使用 `points_ref` 作为 learning frame 会引入额外学习负担，甚至比直接 world supervision 更差 。

**缓解**

* 将 A1/A2 分离；
* 默认先实现 `C0: reference-conditioned-only`；
* 只有 Q1 证明 A2 基本成立后，再升级到 `C1`。

---

### 风险 2：probe-based gate 太重

**问题**
若对每个 reference candidate 都完整跑重模型，gate 成本会接近真正构建 memory。review 已明确指出这一点需要谨慎表述 。

**缓解**

* 两级 gate：light gate 先筛掉大部分 candidate；
* probe 只对 top-M 且通过 light gate 的 reference 执行；
* probe 使用 bounded selector 和小预算；
* 实验中单独比较 `light gate` 与 `probe gate` 的收益/成本比。

---

### 风险 3：single-forward 过选或早停错误

**问题**
只看 coverage 可能过早停；只看 topology 又可能忽略 far-view drift。

**缓解**

* stop 必须同时满足 coverage、topology、ref-risk；
* 设 `min_views` 下限；
* 记录 `stop_reason`；
* 保留 fixed-K 回退开关用于对比。

---

### 风险 4：cluster split 不可控

**问题**
长廊、弱纹理、低共视场景中，split-until-safe 可能不停地 split，但任何子 cluster 仍不满足可行性。

**缓解**

* 强制 `max_num_clusters`
* 强制 `max_split_depth`
* `min_cluster_size`
* `min_views_per_cluster`
* unsplittable cluster 标记为 `low_confidence` 并输出 failure reason
  这必须进入系统定义，不是实现细节 。

---

### 风险 5：cluster branch 中 query-memory 语义不一致

**问题**
query backbone feature 不随 cluster reference 改变，但 memory feature 是 reference-conditioned，若 head/fusion 不知道 cluster 的 reference 语义，可能输出互不一致的 (P_{ref_i})。

**缓解**

* memory tokens 中显式携带 `conditioning_reference`；
* head/fusion 使用 cluster-specific conditioning metadata；
* 第一版不做 learned routing，但必须做 condition-aware fusion。

---

### 风险 6：阈值过多，系统难调

**问题**
coverage、topology、ref-risk、probe 都有阈值，系统容易变复杂。

**缓解**

* 明确分层：

  * light gate 阈值
  * probe gate 阈值
  * single builder 内部 stop 阈值
  * cluster stop 阈值
* 每类阈值只负责一个问题，不混用；
* 输出 reason codes，便于离线分析；
* 优先做 sensitivity study，而不是一开始就复杂调参。

---

### 风险 7：研究问题再次膨胀

**问题**
若同时研究 pooling、backbone、query routing、policy learning，会迅速失控。

**缓解**
明确边界：

* 不研究 pooling
* 不研究 backbone change
* 不研究 learned routing
* 不研究 learned policy
  把问题锁定在 **reference-consistent memory construction** 本身。

---

## 7. Implementation Roadmap

### Phase 0：现有系统插桩与日志统一

**目标**
先不改大逻辑，只让系统“可观测”。

**工作**

* 在 `run_memory_extraction.py` 里统一输出：

  * coverage stats
  * topology stats
  * ref-risk stats
  * probe stats
  * stop reason
* 抽象 memory schema 容器，但先不改变训练/推理行为

**产出**

* 一个可分析的基线系统；
* 后续所有决策都能被日志支撑。

---

### Phase 1：Q1 合同验证原型

**目标**
优先验证 A2，而不是先继续加复杂 policy。

**工作**

* 实现 reference-swap / prediction-equivariance sanity check
* 定义 contract mode：

  * C0
  * C1
* 完成小规模对比实验

**最小可用系统**

* 仍可只走 single-forward
* 但已经能判断默认 contract 应选 C0 还是 C1

这是整个 roadmap 最重要的一步。
如果 A2 站不住，就不能继续默认 ref-coordinate learning。

---

### Phase 2：Single 分支升级

**目标**
完成 single-forward 主路径。

**工作**

* 在现有 `anchor_support_select_views()` 框架上实现：

  * reference-risk-aware TA-ASB
  * adaptive stop
  * topology-constrained repair
* 保留 fixed-K 回退开关

**最小可用系统**

* 只给 `max_views`
* small scene 可自动 early stop
* 输出单 memory

这是第一版可真正替换当前 ASB 的主功能模块。

---

### Phase 3：Two-Level Gate

**目标**
实现 bounded single-domain feasibility decision。

**工作**

* 生成 top-M reference candidates
* 实现 light gate
* 实现 bounded probe gate
* 定义 single-domain existence decision

**最小可用系统**

* 可以自动决定：

  * single-forward
  * cluster branch

此时还不一定要真正跑 cluster branch，可先做 offline decision analysis。

---

### Phase 4：Cluster Planner 与 Best-Effort Fallback

**目标**
补齐大场景路径。

**工作**

* 把 `dataset_origin.py::_cluster()` 抽成独立 helper 
* 实现 split-until-safe
* 加入硬停止条件：

  * `max_num_clusters`
  * `max_split_depth`
  * `min_cluster_size`
  * `min_views_per_cluster`
* 实现 low-confidence best-effort cluster memory

**最小可用系统**

* 大场景能自动 cluster
* cluster 失败可控，不会无限 split

---

### Phase 5：Query-Time Ensemble Interface

**目标**
打通完整 pipeline。

**工作**

* 实现 single / clustered 的统一 query interface
* query backbone feature 只算一次
* cluster-specific independent predictions
* ref->world recovery
* DSAC / inlier-count final selection

**最小可用系统**

* end-to-end 可运行
* single 与 clustered 两条路径都闭环

---

### Phase 6：稳定化与论文级实验

**目标**
从工程系统变成可发表、可比较的方法。

**工作**

* 系统化做 Q1–Q4 实验
* 明确 contract mode 的默认设置
* 报告 gate 成本、误判案例、cluster fallback 行为
* 写清楚：

  * light gate vs probe gate
  * C0 vs C1
  * always single vs always clustered vs auto-policy

---

### 推荐实现顺序

最优顺序不是“先做最复杂的 selector”，而是：

1. **先做 Q1 contract validation**
2. **再做 single-forward selector + auto-stop**
3. **再做 two-level gate**
4. **最后做 cluster fallback**

原因很明确：
整个系统的真正地基是 contract，而不是选帧分数。最新 review 已经把这一点说得非常清楚：如果 A2 不成立，后面所有 reference-coordinate 设计都需要降级 。

---

这版最终方案的核心结论可以压缩成四句话：

* **先验证并固定 reference-local contract，再谈 policy。**
* **single 分支的目标不是“好看的图”，而是构造一个 single-reference-safe domain。**
* **large-scene 决策不是 scene-size threshold，而是 single-domain feasibility test。**
* **cluster 分支第一版只做 independent ensemble fallback，不引入 learned routing 和 cross-cluster fusion。**

这就是我认为结合代码现状、所有 review、以及工程可落地性之后，最完整、最稳的最终系统设计。
